# 健康数据录入契约

`Personal/` 按人分区，每个人的健康数据在 `Personal/<Dir>/Health/`。任何 agent（Codex / Claude Code / WorkBuddy / Grokbot …）读写健康数据都按此契约来；格式的唯一定义在 deepfy-health 仓库的 `src/core/schema.ts`，写完一律跑 `kzh validate`。

## 目录

```
Personal/
  Personal.md                       成员索引
  family.yaml                       成员名册（id / name / role / dir）
  _health/
    健康数据录入契约.md              本文件
    indicators.yaml                 自定义指标（与内置字典合并，`kzh catalog` 查看全部）
  <Dir>/                            一个人（如 KZ/）
    <Dir>.md                        个人主页：各板块入口（健康、工作、兴趣、保险…）
    兴趣爱好.md  保险配置.md         其他板块，分析时可作为背景参考
    Health/
      Health.md                     健康索引（链接 profile / regimen / care-plan）
      profile.md                    档案卡（frontmatter 是结构化数据，正文是自由补充）
      records/<YYYYMMDD 主题>.md     一次检测记录（如 `20261015 年度体检.md`）
      attachments/                  原始报告 PDF / 图片
      indicators/<CODE>.md          单项指标的分析笔记（只为异常或需要关注的指标写）
      regimen.md                    用药 / 补剂计划（定时任务读这里）
      care-plan.md                  整体调养方案
```

下文的相对路径（`records/`、`profile.md` …）都相对于 `Personal/<Dir>/Health/`。分析时可以读同一个人目录下的其他板块（如作息、运动爱好、保险）作为背景，但只写 `Health/` 和 `_health/`。

日期一律 `YYYY-MM-DD`。没填的字段留空或删掉，不要编造。

## 流程 A：录入一份体检报告 / 化验单

1. 原始文件放进 `attachments/`，文件名 `<YYYYMMDD> <机构或类型>.pdf`。
2. **全面**抽取：先通读每一页（含附页、影像 / 心电图报告、总检结论），列出报告有哪些部分，再逐项抽取——一般检查（身高 HEIGHT、体重、BMI、血压、脉搏）、血常规、尿常规、肝肾功能、血脂、血糖等，以及**检查结论**（心电图 ECG、腹部超声 US_LIVER / US_GALLBLADDER / US_PANCREAS / US_SPLEEN / US_KIDNEY、甲状腺 / 乳腺 / 前列腺 / 颈动脉超声、胸片 CHEST_XRAY、胸部 CT CHEST_CT、眼底 FUNDUS、口腔 DENTAL 等，写成文字值，如 `{ code: US_LIVER, value: "轻度脂肪肝" }`）。用 `kzh catalog --search <报告上的名称>` 把每项对齐到 code；内置没有的，先在 `_health/indicators.yaml` 增加条目（code 用大写英文 + 下划线）。报告是拍照 / 截图 / App 页面 / 表格时同样要求全面；看不清的数字问用户，不猜；一份文件里有多个日期时按日期拆成多条记录。
3. 新建 `records/<YYYYMMDD 主题>.md`：

```yaml
---
date: 2026-10-15
type: checkup          # checkup=年度/全面体检（用于年度提醒）| lab=单项化验 | device=家用仪器 | manual=手动
title: 2026 年度体检
institution: 某某体检中心
attachments: ["attachments/20261015 年度体检.pdf"]
indicators:
  - { code: ALT, name: 谷丙转氨酶, value: 68, unit: U/L, ref_low: 9, ref_high: 50 }
  - { code: U_PRO, name: 尿蛋白, value: "阴性", ref_text: 阴性 }
  - { code: US_LIVER, name: 腹部彩超-肝脏, value: "轻度脂肪肝" }   # 检查结论：文字值，非正常描述判 A
---
总检结论与医生建议原文；本次要点一两句。
```

   - **参考范围以报告上印的为准**（`ref_low` / `ref_high` / `ref_text`），报告没印才省略，由 catalog 兜底。
   - `value` 原样照抄；数值写数字，定性结果写字符串。
   - `flag`（H / L / N / A）可省略，程序会按范围计算；报告上标了↑↓且与范围矛盾时，以报告为准写上 `flag`。
   - 字典里查不到合适 code 的项目放进 `other_items`（`{ name, value, unit, ref_text, section }`），不要编 code；易混项看 `kzh catalog --search` 结果里的说明（如全血微量元素 ≠ 血清钙镁 ≠ 铁蛋白，Hp 抗体 ≠ 呼气试验，血小板压积 PCT ≠ 降钙素原）。
   - 单位与 catalog 不同（如 mg/dL vs mmol/L）时照抄报告单位，`kzh validate` 会给出警告，在正文里说明。
4. 对**异常或明显变化**的指标，新建或更新 `indicators/<CODE>.md`：

```yaml
---
code: ALT
updated: 2026-10-20
status: attention      # attention=需要处理 | watch=继续观察 | normal=已恢复
summary: 轻度升高，多与脂肪肝、饮酒、熬夜相关     # 一句话，网站列表直接显示
recheck: 2027-01-15    # 可选，建议复查日期，会进入提醒
---
## 解读
偏高/偏低通常意味着什么；结合 profile.md 里的年龄、性别、病史、习惯和历史趋势（`kzh series <id> ALT`）给出具体判断。
## 饮食
## 作息与运动
## 何时就医
```

5. 更新 `care-plan.md`（`focus` 列出重点指标 code，正文给出整体调养方向），保持简洁、可执行。
6. 药物只记录医生开的或用户明确在吃的，不要建议开始、停用、换药或改量。补剂可以结合档案建议，写 `status: suggested`、`source: agent`，用户同意后再改成在用（去掉 `status`）。更新 `regimen.md`：

```yaml
items:
  - id: vitd3
    name: 维生素D3
    kind: supplement     # medication | supplement
    dose: 2000 IU
    times: ["08:00"]
    days: [mon, wed, fri] # 可选，不写=每天
    with_food: true
    start: 2026-10-20
    end: 2027-01-20       # 可选，到期前会提醒复评
    reason: 25-羟基维生素D 偏低
    related: [VITD]
    doctor_confirmed: false
    # 以下都可选
    status: suggested     # suggested 建议中（只有补剂能用）| active 在用（默认）| stopped 已停用（要写 stopped_on）
    source: agent         # prescribed 医生开的 | self 自己买的 | agent agent 建议
    frequency: 每日 1 次   # 不知道具体钟点时用，times 可不写
    as_needed: false      # 按需，不进今日定时安排
    precautions: [随餐吃吸收更好]
    brand: 示例品牌
    spec: 每粒 D3 2000 IU
    expiry: 2027-06-30    # 有效期至，临近时提醒
```

7. 跑 `kzh validate --pretty`，直到 0 个错误。

## 流程 B：建档 / 更新档案

- 新成员：`kzh init-member <id> --name 名字 --dir 目录名 --sex male|female --birth YYYY-MM-DD`，会生成个人主页、兴趣爱好、保险配置和 `Health/` 下的模板，并登记到 `family.yaml` 与 `Personal.md`；再补全 `profile.md`。
- 身高体重等变化：更新 `profile.md` 的 frontmatter 和 `updated`；家用仪器的数值（体重、血压、血糖）另记一条 `type: device` 的 record，以便看趋势。

## 流程 D：快速记录（症状 / 备注 / 照片）

不需要完整报告也能建档。一次症状或备注写一条 `logs/<YYYYMMDD-HHmm>.md`（同一分钟多条加 `-2`、`-3`）：

```yaml
---
date: "2026-10-28"
time: "22:30"          # 可选
type: symptom          # symptom 症状 | note 备注
title: 连续加班后头晕   # 一句话
severity: 2            # 可选，1 轻 / 2 中 / 3 重
tags: [头晕, 熬夜]      # 可选，便于和指标、体检建议关联
attachments: []        # 照片放 attachments/logs/<key>-1.jpg，写相对 Health/ 的路径
---
详细描述：什么时候开始、持续多久、诱因、缓解方式。
```

体重、血压、心率、空腹血糖等单次数值记成 `type: manual` 的 record，文件名 `YYYYMMDD 日常记录.md`，同一天合并在一条里。网页「快速记录」写入的就是这两种格式。

## 流程 C：定时任务读取

- `kzh regimen today [<id>]` → 今天每个时间点要吃什么
- `kzh reminders` → 年度体检、复查、补剂复评到期
- `kzh abnormal <id>` / `kzh member show <id>` → 当前状况

## 分析原则

- 结论要结合个人数据：同样的数值，对不同年龄、性别、病史、习惯的人含义不同。
- 说清楚「常见原因」与「需要就医的信号」，不做诊断，不建议自行停药或改药量。
- 只写有依据的内容；不确定就写「建议咨询医生」。
