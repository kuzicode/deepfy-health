# 问题记录与经验教训

每次解决一个非平凡 bug / 踩坑 / 设计反复后追加一条。

**查阅规则**：先读头部索引表，再按 `## ISS-XXX` 定位读单条，不整文件读。

**维护规则**（agent 必读）：

1. **新 ID = 索引表最大编号 + 1**。先查索引表再追加，禁止凭记忆编号。
2. 正文一律 **newest-first**：新条目插在索引表之后的第一个位置。
3. 每次增改条目，同步更新索引表对应行。
4. **归档阈值**：正文超过 ~200 行或 resolved 条目超过 ~15 条 → 将最旧的 resolved 条目整体迁入 `issues-archive.md`，索引行保留、位置改 `archive`。`open` / `superseded` 条目永不归档。
5. 状态：`open` / `resolved` / `superseded`。本文件是问题状态的唯一权威（HM4）。
6. **经验升级**：同类坑第二次踩中、或某条「经验」被第二次引用 → 把它提炼为 `docs/conventions.md` 条目或 AGENTS.md 编号硬规，并在原条目「经验」行尾标注 `（已升级 → 位置）`。经验的终点是规则，不是档案。

## ISS-020 — 请求体限制可绕过；磁盘不足后清理不会触发 [resolved]

- **现象**：①`/mcp` 和 `/api/v1/import` 只检查 `Content-Length`，分块发送时整个请求体都会被读取，`/mcp` 还是在拿并发名额之前读的。反向代理的大小限制仍然有效，主要影响没有反向代理的实例。②附件旧文件只在上传成功后清理，可用空间低于 5 GB 时上传失败，清理就永远等不到触发。
- **修复**：`readBodyLimited` 按实际读取的字节数限制，`/mcp` 先拿并发名额再读取。空间不足时先清理再复查，每日任务也清理一次。
- **经验**：大小限制不能只看请求头；依赖某个操作成功才触发的清理，在这个操作失败时不会运行。

## ISS-018 — 公开前安全审查：Google 未验证邮箱可关联已有账号等 [resolved]

- **日期**：2026-11-06（公开前审查，阅读 better-auth 源码确认，未对 Google 实际复现）
- **现象**：① `trustedProviders` 含 `google`，会跳过「Google 邮箱已验证」的检查。如果 Google 返回 `email_verified=false` 的身份，也能关联到同邮箱的已有账号。② 重置密码不结束已有会话。③ 验证码校验只按邮箱计数，别人输错 30 次就能让邮箱主人当天无法用验证码登录（ISS-017 的修复带来的）。④ 附件上限 30 MB，大于请求体 26 MB 的截断阈值，超过阈值的文件可能被截断后仍返回成功（由源码推断，未复现）。
- **根因**：① 把 `trustedProviders` 当成「允许合并账号」的开关，实际上它是「不看对方是否验证」。② better-auth 默认不结束会话。③ 限次只考虑了防猜，没考虑防锁。④ 两处上限分开定义。
- **修复**：去掉 `trustedProviders`，校验钩子拒绝未验证的 OAuth 身份；`revokeSessionsOnPasswordReset`；校验按邮箱 + IP 每天 30 次，邮箱合计 300 次兜底；所有发验证码的接口都按 IP 限次；附件上限 25 MB，读取请求体前先看 `Content-Length`；解密固定 16 字节认证标签。
- **经验**：库的配置项要读它在源码里跳过了什么，不能只看名字。限次要同时问两个问题：能不能防猜，会不会被别人用来锁住账号主人。

## ISS-017 — 抢先用别人邮箱注册后，验证时保留抢注者的密码 [resolved]

- **日期**：2026-11-06（开源前审计，本地实例复现）
- **现象**：攻击者先用受害者邮箱注册并设密码；受害者再注册时接口同样返回 200，验证邮箱后账号生效的是攻击者的密码，受害者自己的密码返回 401。另外，验证码明文存库；校验次数只按 IP 限制，可以换 IP 分散猜。
- **根因**：better-auth 的 `verify-email` 不作废验证前设的密码（`sign-in` 那条路径会）。按邮箱的限次只管发信，超限后验证码仍会轮换，校验也不受限。
- **修复**：`beforeEmailVerification` 删除未验证账号的密码，验证成功后由 `setInitialPassword` 设置用户刚输入的密码；`storeOTP: "hashed"`；校验接口按邮箱每天 30 次；限速只信 `X-Real-IP`。Google 不受影响（`requireLocalEmailVerified` 默认开启，不关联未验证账号）。
- **经验**：邮箱未验证前收到的凭据都不可信，所有权证明之后才能算数。按防枚举设计返回 200 的注册接口，要单独测「邮箱已被占用」时后续流程的结果。审计时要对照「明文存了什么」和「对外怎么说」，这次还查出「备份里只有密文」不准确。

## ISS-016 — 用药表单丢关联、采纳过期建议日期倒置 [resolved]

- **日期**：2026-11-05（代码 review）
- **现象**：① agent 关联了还没测过的指标，网页上只改备注，保存后关联被清空。② 11-05 采纳结束日期为 11-03 的建议，保存成功，状态是在用，当天安排却为空。
- **根因**：① 表单只列有结果的指标，保存却整体替换 `related`。② 采纳时只把开始日期改成今天；日期倒置只作为警告，页面还不显示这条警告。
- **修复**：表单选项补上已关联的指标（`relatedOptions`）；写入层拒绝倒置日期（网页和 MCP 共用 `mergeItem`），去掉不再需要的 `date_order` 警告；网页采纳带结束日期的建议时先确认，已过期的不预填。
- **经验**：表单整体替换一个字段时，选项必须覆盖该字段的现有值，否则没显示的值会被静默删除。会改写日期的操作要校验改写后的结果。

## ISS-015 — Google 登录被拒后无法提交申请 [resolved]

- **日期**：2026-11-05（朋友反馈）
- **现象**：未开通的 Google 账号登录后回到 `/login?error=not_allowed`，提示「可以先申请」，但页面只有登录表单。只有重新输入邮箱并点「继续」才会进申请表，于是用户以为申请过了，后台没有记录。
- **根因**：申请表只能从「邮箱分流」进入，错误提示指向一个当前页面没有的操作。
- **修复**：登录页加独立申请入口，填邮箱就能提交；`not_allowed` 直接进申请表；`applyForAccess` 让已开通的邮箱不进候补，转去登录。
- **经验**：错误提示让用户做的下一步，当前页面必须能直接做。

## ISS-014 — agent 录入化验报告的系统性问题 + 0.17 review [resolved]

- **日期**：2026-11-04（档案录入复盘）
- **现象**：①「血糖(随机)」被映射成 FBG（字典别名「葡萄糖」只指向空腹）；② agent 把日期写进标题，key 变成「日期 日期 标题」，且 MCP 不能删、改名后另起一条；③ 过敏原等 other_items 标了 H 但记录异常数为 0、概览看不到；④ 单项彩超 / CT 用 type=checkup，顶替了「上次体检」；⑤ 彩超结论里的术语被改写成意思相近、含义不同的词，RA/RV 混淆；⑥ review：概览链接把报告名放进 `?open=` 会进 nginx 访问日志；随机血糖用 11.1 当正常上限；第一次替换后标题已清理，第二次替换又另起一条；心率 bpm / 次/分 在趋势里丢点；提醒测试因随机 id 含「88」偶发失败。
- **根因**：字典与录入规则没覆盖这些常见写法；服务端对 agent 的输入没有兜底；单位只在校验处做了等价，趋势和较上次没复用；测试断言范围过宽。
- **修复**：字典加 GLU_RAND（不设兜底范围）、US_HEART、Lp(a) 备用单位 nmol/L、单位同义（bpm = 次/分，趋势与较上次共用）；`stripDatePrefix` + 替换时识别两种旧 key；other_items 异常计入列表与概览（`other_abnormal`）；契约写明 checkup 只用于全面体检、结论照抄原话、症状记日志、看不清的图片逐张告知；记录页用 URL 片段定位；断言只检查邮件内容。
- **经验**：复盘 agent 的实际写入结果，比读代码更快暴露规则缺口；含健康信息的字符串不要进 URL 查询参数（会落进访问日志），定位用片段。

## ISS-013 — 官网匿名请求全部由 Node 渲染、压测下反代连接耗尽 [resolved]

- **日期**：2026-11-04
- **现象**：压测时应用没有崩溃，`/mcp` 的应用限速正常返回 429，但官网页面吞吐很低，反代连接被耗尽后不再接受新连接。
- **根因**：根布局 `force-dynamic`，官网每次请求都由 Node 渲染并回 `no-store`；反代层没有缓存和按 IP 限速，所有请求先到 Node；容器没有资源上限。
- **修复**：官网公开页和静态资源在反代层缓存，反代层按 IP 限速和限连接，`compose.yml` 给容器加资源上限。
- **review 追加修复**：缓存键忽略 `Vary` 时，RSC 组件数据和 HTML 会互相串，所以 RSC / 预取请求（`RSC`、`Next-Router-*` 头或 `_rsc` 参数）必须绕过缓存并回 `private, no-store`；整包 `zipSync` 导出大附件会 OOM，改为 `src/server/zip-stream.ts` 流式打包；官网域名不能绕过应用限速。
- **经验**：内容人人相同的匿名页面要么静态生成，要么在反代层缓存，不能让每个匿名请求都打到 Node。

## ISS-012 — 额度检查与写入不原子等 Codex review 问题 [resolved]

- **日期**：2026-11-04
- **现象**：①并发创建 6 个 token 成功 5 个（免费档 3 个），附件上传同理；②已有 199 条 agent 写入时，一次 update_schedule 改 30 项仍能通过，达到 229 条；③脚本首次运行时直接退出。
- **根因**：①额度在事务外「先查后写」，并发请求都读到「还没超」；②写入前只按 1 条预扣，没按实际会产生的修改记录条数；③`find` 目标目录不存在时失败，`set -euo pipefail` 下脚本退出，后面的 `mkdir` 没执行。
- **修复**：`lockUser`（与 PgRepository 共用的账号 advisory lock）内用同一事务检查额度再写入（token、附件、家人、agent 写入）；`applyChanges` 在锁内按 put / create 条数检查；脚本先 `mkdir -p` 目标目录。
- **经验**：任何「检查上限 → 写入」都要在同一把锁 / 同一事务里，并按这次实际要写的数量检查，而不是固定 +1。

## ISS-011 — 否定结论被判正常等 Codex review 问题 [resolved]

- **日期**：2026-11-03 – 2026-11-04
- **现象**：①「非正常心电图」「心电图不正常」「abnormal」「Abnormal ECG」「not normal」判为正常，异常从「需要关注」消失；②「高血压（未治愈）」「unresolved」被当成已愈收进既往病史；③没有体检记录但手动定了日期的首次体检，邮件任务直接跳过；④反馈表单连续提交后切换类型清空草稿；⑤审查环境 `pnpm test:db` 报 `code.charCodeAt is not a function`。
- **根因**：①「主语 + 正常词」只拦中文异常描述，没考虑否定词，英文没有词边界（abnormal = ab + normal）；② `已愈|治愈` 子串匹配不看前面的「未 / 尚未」；③邮件任务用「有没有上次体检」区分「未安排」，漏了手动日期；④表单 key 用 `Date.now()`，每次渲染都重挂载；⑤测试库连不上时，vite 的 source map 处理在格式化连接错误堆栈时崩溃，盖住了 ECONNREFUSED。
- **修复**：`subjectThenNormal` 加中英文否定与词边界（`isPlainSubject`）；`isResolved` 先剔除否定短语再匹配；体检待办加 `params.scheduled`；去掉表单 key（React 19 action 完成后自动重置）；`src/test/global-setup.ts` 捕获后抛一句明确提示。
- **经验**：文字结论的「正常」匹配第三次出问题——任何放宽都要配否定反例测试（已升级 → `docs/conventions.md`「健康数据展示」）。测试启动报奇怪的内部错误时，先确认外部依赖（数据库端口）可达。
